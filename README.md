# BERT 中文情感分析

用 BERT 做中文**电商评论**情感分类（好评 / 差评），从数据处理、训练、评估到 Web 演示的完整工程实现。

> **适用域说明**：本模型的训练语料是电商评论，因此**负面识别可跨领域泛化，
> 正面识别只在电商域内可靠**。实测数据与原因见 [模型适用域](#模型适用域重要) 一节。

这个仓库有**两个版本**，v2 是在 v1 基础上重写的优化版：

| 版本 | 说明 |
|---|---|
| **`v2/`** | **推荐看这个。** 修复了数据泄漏、建立独立测试集、加了置信度校准与误差分析、批量推理提速 12–20 倍 |
| `V1/` | 第一版的忠实归档，作为「改造前」的对照基准 |

## 亮点一览

- **发现并修复数据泄漏**：旧版测试成绩虚高，因为测试集 99.9% 落在它的训练数据源里
- **零泄漏测试集**：910 条独立样本，准确率 **91.10%** / Macro-F1 **0.9107**
- **置信度校准**：温度缩放把 ECE 从 0.069 降到 0.046
- **三层判定机制**：内容合法性 → 模型推理 → 置信度阈值，42 条单元测试
- **选择性预测**：对最有把握的 83.6% 样本给出结论，此时准确率 **95.80%**
- **批量推理**：一次前向 128 条，提速 12–20 倍
- **诚实的边界说明**：明确标注适用域与已知短板（见「模型适用域」）

```bash
git clone <本仓库地址>

# 3. 微调模型（有 GPU 约 4 分钟）

# 4. 在独立测试集上评估
```

只想快速试一下效果，可以跳过第 5 步直接用命令行：

```bash
python cli.py
```

### ⚠️ 两个已知环境问题（代码里已处理，这里说明原因）

**1. 目录名含中文会让 PyTorch 保存失败。**
本项目目录名带「项目3：」（含全角冒号），而 PyTorch 2.0 在 Windows 上保存文件时
如果收到含中文的绝对路径，会误报 `Parent directory ... does not exist`。
`train.py` 里已打补丁（包装 `torch.save`，先转成文件对象再写入）绕过这个问题。
**如果你把项目 clone 到一个纯英文路径下，就不会遇到这个问题。**

**2. 首次运行需要联网下载预训练模型。**
`bert-base-chinese` 的权重约 400 MB，首次运行 `train.py` 时会从 HuggingFace 镜像
自动下载。国内建议设置镜像（`config.py` 里已默认设置）：

```bash
export HF_ENDPOINT=https://hf-mirror.com
```

下载完成后，`config.py` 里的离线开关会自动让后续运行直接读本地缓存，不再联网。
**如果你换了别的预训练模型**，需要先把 `config.py` 里的
`HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` 两行注释掉，跑一次让它下载，下完再恢复。

## 技术要点

- **数据泄漏防治**：划分结果物化落盘为固定文件，训练脚本在代码层面够不到测试集
- **主指标用 Macro-F1**：准确率在类别不均衡时会骗人，Macro-F1 对两类一视同仁
- **置信度校准**：温度缩放（Temperature Scaling），ECE 从 0.069 降到 0.046
- **误差自动归因**：把错误分成否定/贬义、长文本截断、转折结构等六类
- **批量推理**：一次前向算 128 条，实测提速 12–20 倍
- **三层判定机制**：解决"二分类器被迫对无关内容也给出好评/差评"的问题，见下节
- **适用域边界实测**：跨领域验证出"负面可泛化、正面退化"的规律，见「模型适用域」

## 三层判定机制（拒识设计）

### 问题

模型是二分类器，最后一层 `Linear(768, 2)` 接 softmax，两个概率恒和为 1。
它**没有"无情感"这个选项**，所以面对 `1234567`、`帮我写首诗`、`今天天气不错`
这类输入，它只能强行二选一，而且常常给出很高的置信度。

### 方案

在二分类模型外面套三层闸门，只有同时通过三层的文本才给出好评/差评：

| 层级 | 判据 | 输出 |
|---|---|---|
| ① 内容合法性 | 长度、中文字符占比、指令句、疑问句、日常陈述句（纯规则，不依赖模型） | `非评论内容` |
| ② 模型推理 | BERT 前向 + 温度缩放校准 | — |
| ③ 置信度阈值 | 最大概率 < `uncertain_threshold` | `情感不明显` |

第一层闸门的具体检查顺序（`inference.check_comment`）：

1. 空输入
2. 纯数字 / 纯符号（`1234567`、`!@#$%`）
3. 中文字符数 < 2
4. 内容过短（< 3 字；恰好 3 字时要求含情感词，否则拦 —— 兼容"太贵了"这类 3 字短评）
5. 中文占比 < 15%（中夹英的代码、URL、编号串）
6. 指令句式（`^帮我`、`^请写`、`^翻译`）
7. 疑问句式（问号收尾 / 疑问词收尾且短 / 含疑问词+短+无情感词）
8. **日常陈述句**（无情感词、无程度副词、无标点、短句且含第一人称或日常动作词）→ `我吃饭了`、`今天上课`

第 8 条的设计取舍：**宁严勿松**。像"手机到了""快递拿回来了"这类
没有情感词的句子仍会放行给模型，由置信度阈值兜住。误伤清单经过
21 条真实评论句式的回归验证，误伤 0 条。

阈值取 **0.95**，依据来自 `evaluate.py` 输出的覆盖率-准确率表：

| 阈值 | 覆盖率 | 准确率 |
|---|---|---|
| 0.80 | 94.9% | 93.29% |
| 0.90 | 90.8% | 94.31% |
| **0.95** | **83.6%** | **95.80%** |

含义：只对最有把握的 83.6% 样本给结论，此时准确率 95.80%；剩下 16.4% 交人工复核。
这是**选择性预测**的用法，比硬答更有工程价值。

> **为什么不用更宽松的阈值？**
> 极短文本（如"太贵了"）在二分类模型上置信度天然偏低，0.95 会让一部分
> 短评落入"情感不明显"。这是**有意的取舍**：短文本信息量少，
> 说"不确定"比硬判一个方向更谨慎，也避免了误报。
> 若要覆盖更多短评，可下调到 0.90（覆盖 90.8%、准确率 94.31%），
> 但会牺牲整体准确率。

## 模型适用域（重要）

本模型的定位是**电商评论情感分析**，不是通用情感分类器。
这一节说明它的能力边界，以及为什么存在这个边界。

### 跨领域实测

拿 16 条**非电商**评论（影视 / 音乐 / 餐饮 / 书籍 / 旅游 / 课程 / 游戏 / App）
直接送进模型，结果呈现一个非常清晰的模式：

| 类型 | 判定情况 |
|---|---|
| 负面跨领域评论 | **8 条中 7 条判对**，置信度 97%+ |
| 正面跨领域评论 | **8 条中仅 1 条判对**，其余落入"情感不明显"（54%~92%） |

```
差评 97.6%   烂片一部，浪费时间，看睡着了            ← 跨领域负面：准
差评 97.9%   内容空洞，全是废话，翻了几页就放弃了      ← 跨领域负面：准
情感不明显 62.3%  这首歌旋律特别好听，单曲循环一整天      ← 跨领域正面：退化
情感不明显 54.5%  风景美得不像话，值得专门跑一趟        ← 跨领域正面：退化
好评 98.1%   界面简洁，操作流畅，比同类软件好用多了      ← 软件域，词与电商接近
```

### 原因

训练语料中**负面样本的表达方式集中且强烈**（"烂""差""再也不买"），
这类词汇信号在跨领域时依然有效；而**正面样本高度依赖电商套话**
（物流、包装、客服、性价比），一旦换成"旋律好听""逻辑清晰""风景美"，
模型便无法识别，置信度随之掉到阈值以下。

值得说明的是：**模型的"情感不明显"在这里是正确的保守行为** ——
它没有把正面评论误判成差评，只是拒绝给出结论。这正是三层判定机制的价值。

### 如果要扩展到通用评论

需要补充**非电商领域的中文评论数据**（影评 / 书评 / 餐饮等，带正负标签）
混合训练。这是 v3 的可选方向之一。

## v3 规划（未实现）

按性价比排序：

1. **通用领域扩展**（性价比最高）
   补充跨领域评论数据，把"电商评论二分类"升级为"通用评论二分类"。
   实测已证明瓶颈在**正面样本的域单一**，补数据即可解决，
   不需要改动模型结构。

2. **中性类三分类**
   把标签改成 `负面 / 中性 / 正面` 重训，让"我吃饭了""还行吧"
   由模型自己归到"中性"，从根上减少对规则闸门的依赖。
   难点在**中性样本的标注口径**（"还行"算中性还是弱正面，边界有争议）。

3. **OOD 检测**
   在表示空间做离群检测（MSP / Energy / ODIN），替代部分规则闸门。
   学术味更重，但阈值调参成本高，收益不如前两项直接。
