## 一、项目简介

本项目基于 `bert-base-chinese` 预训练模型微调，实现中文电商评论的**好评 / 差评**二分类，  
并提供 Web 端单条与批量分析能力。

项目重点不在于"跑通一个 BERT 分类器"（这是入门任务），而在于解决一个 NLP 项目上线前的  
三个真实工程问题：

| 问题                     | 本项目给出的答案                          |
| ---------------------- | --------------------------------- |
| **模型说自己 99% 有把握，真的吗？** | 温度缩放校准，把置信度对齐到真实准确率，ECE 显著下降      |
| **怎么保证测试集没被污染？**       | 三路划分 + 物理落盘隔离，训练脚本在代码层面够不到测试集     |
| **几千条评论要跑十几分钟？**       | 真正的分批推理，替换逐条前向传播，实测提速 **12～20 倍** |

## 二、核心特性

### 1. 数据层面：从流程上杜绝泄漏

- 原始 10,800 条 → 清洗去重后 **9,097 条**（删除 1,703 条完全重复样本）
- 按 **8:1:1** 分层抽样切分 train / val / test，并**物化为固定文件**
- 内置 `leak_check()` 自动检测三份数据之间的文本交集，输出体检报告
- 训练脚本只读 `train.csv` / `val.csv`，**在代码层面无法访问测试集**

### 2. 训练层面：标准 BERT 微调配方

| 技术点     | 旧版             | 新版                            |
| ------- | -------------- | ----------------------------- |
| 训练框架    | 手写训练循环         | HuggingFace `Trainer`         |
| 学习率策略   | 恒定 `2e-5`      | 线性预热 10% + 线性衰减               |
| 混合精度    | 无              | FP16（速度约 2×，显存约 0.5×）         |
| 早停      | 无（固定跑 3 轮）     | 监控 Macro-F1，patience=2        |
| 选模型标准   | 准确率            | **Macro-F1**（对类别不平衡更鲁棒）       |
| Padding | 全量固定 pad 到 128 | **动态 padding**（按 batch 内最长样本） |
| 随机种子    | 未固定            | Python / NumPy / Torch 三层固定   |

### 3. 评估层面：做真正有说服力的分析

- 完整指标组合：Accuracy / Macro-F1 / Weighted-F1 / **ROC-AUC** / 分类别 P、R
- **可靠性曲线**（Reliability Diagram）：直观展示校准前后的置信度可信度变化
- **置信度分桶统计**：给出"阈值—覆盖率—准确率"三者关系，输出可运营的阈值建议
- **错误案例自动归因**：把错误归纳为长文本截断 / 转折结构 / 否定作用域 / 抱怨式好评 / 反讽 / 标注疑似有误六类

### 4. 推理与部署层面

- **温度缩放校准**：在验证集上拟合标量 T，只改变置信度、不改变预测结果
- **真正的批量推理**：`batch_size=128` 一次前向传播处理 128 条，实测提速 12～20×
- Web 端提供单条分析、批量分析、文件上传、可视化图表
- `/health` 健康检查接口，便于部署监控

## 四、快速开始

### 环境准备

本项目在以下环境验证通过：

- Python 3.10.11 / 3.12.7
- PyTorch 2.0.1+cu118（CUDA 11.8）
- transformers 4.30.0
- Flask、scikit-learn、pandas、matplotlib、seaborn

```bash
# 安装依赖（把 python 换成你自己的解释器路径）
python -m pip install -r requirements.txt
```

> **关于 PyTorch 版本**：如果有 NVIDIA 显卡，强烈建议去 [pytorch.org](https://pytorch.org)  
> 按显卡的 CUDA 版本选对应安装命令。装成 CPU 版本的 PyTorch 会让训练慢几十倍。

### 四步跑通

```bash
cd v2/src

# ① 准备数据：清洗 + 三路划分 + 泄漏自检（只跑一次）
python prepare_data.py

# ② 训练模型：微调 BERT（有 GPU 约 10~20 分钟）
python train.py

# ③ 评估模型：在独立测试集上出指标 + 拟合校准参数
python evaluate.py

# ④ 启动演示：浏览器打开 http://127.0.0.1:5000
python web_app.py
```

### 命令行工具（不想开浏览器时用）

```bash
python cli.py
```

支持 `:file <路径>` 批量预测文件、`:info` 查看模型信息。

| ----------------- | --------------- | ------------------- |

| Weighted-F1       | 0.9111          | —                   |
| **ROC-AUC**       | **0.9681**      | 反映区分能力，不受分类阈值影响     |
| 差评 精确率 / 召回率      | 0.8922 / 0.9196 | 差评召回更高——业务上漏判差评代价更大 |

错误率 8.90%（81/910），错误自动归因：**否定/贬义词 33.3% > 长文本截断 29.6% > 转折结构 27.2% > 反讽 4.9% ≈ 抱怨式好评 4.9%**。

### 关于旧版"97%"的说明（答辩必读）

把旧模型放到这份测试集上跑分，能得到 97.03%——比新模型还高。  
但查证旧版 train.py 后确认：**它读取的是未去重的 large_data.csv 全量（10,800 条），  
而这份测试集 910 条中有 909 条（99.9%）都在它的训练数据源里**——  
8:2 切分后它实际"背过"约八成测试题，1,703 条重复样本进一步放大了记忆效应。

所以旧版的任何评估数字都无法解释为泛化能力，这正是本次升级要解决的根本问题。  
**91.10% 是本项目第一个可以写进 PPT 的真实数字。**

## 六、关键技术说明

### 为什么主指标用 Macro-F1 而不是 Accuracy？

假设测试集 90% 是好评，那么一个"全部预测成好评"的废模型也能拿到 90% 准确率。  
但它在业务上一文不值——差评全被漏掉了。

Macro-F1 对两个类别一视同仁地计算 F1 再取平均，  
能真实反映"差评有没有被识别出来"。对电商场景，  
**漏判差评的代价远高于漏判好评**，所以这个指标更贴近业务目标。

### 温度缩放在做什么？

神经网络有系统性"过度自信"倾向：它说"99% 确定"时，真实正确率往往只有 80% 左右。

温度缩放的做法是：在 softmax 前把 logits 除以一个标量 T。

$\text{softmax}(z/T)$

- `T > 1`：概率分布变平坦，置信度下降
- `T < 1`：概率分布变尖锐，置信度上升

T 由验证集上的 NLL 最小化拟合得到，它**不改变 argmax 结果**，  
所以准确率、F1 等指标完全不受影响，只让置信度变得可信。

验证方式：项目在 `calibration.json` 里记录了 `accuracy_unchanged: true`，  
这就是"校准是安全的、纯后处理"的证明。

### 分批推理为什么能快这么多？

深度学习计算有个特性：矩阵乘法的耗时**对矩阵宽度相对不敏感**。

处理 1 条样本耗时约 22ms，处理 128 条一起耗时约 68ms——  
干的活多了 128 倍，时间只多了 3 倍。这正是 GPU 的设计意图：  
用大规模并行掩盖单次运算的延迟。

旧代码 `for text in texts: predict_single(text)` 的写法，  
每次只喂给 GPU 1 条数据，GPU 大部分时间在空转等数据传输。

## 七、已知局限与后续方向

诚实说明项目边界，这在答辩和面试中比夸大效果更有说服力：

1. **数据域较窄**：训练数据为电商/酒店评论，迁移到社交媒体、新闻评论等领域效果会下降。  
   后续可引入跨域数据和领域自适应训练。
2. **二分类粗粒度**：目前只能区分好/差评，无法给出"物流""质量""客服"等维度的细粒度情感。  
   后续可改为多标签分类。
3. **长文本截断**：`max_len=128` 会把长评论截断（错误分析中占比不低）。  
   后续可改用滑动窗口或层次化建模。
4. **未做对抗鲁棒性测试**：对错别字、谐音梗、表情包的鲁棒性未评估。
5. **模型规模**：使用 `bert-base-chinese`（1.02 亿参数）。  
   换成 `hfl/chinese-roberta-wwm-ext` 或 MacBERT 通常还能提升 1～2 个点。
